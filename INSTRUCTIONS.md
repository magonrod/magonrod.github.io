# Portfolio Instructions

This repository contains my professional portfolio website.

Before making career-related or portfolio-content decisions, read:

CAREER_CONTEXT.md

Use that file to understand:
- my background
- my projects
- the work I am targeting
- my career priorities
- how my experience should be positioned

## Main objective

The portfolio should position me strongly for technical roles involving
modelling, simulation, scientific computing, optimisation, dynamics,
space systems, defence or robotics.

Prioritise technical credibility and clarity over decorative design.

The website should be:
- concise
- technically credible
- easy to scan
- visually clean
- focused on my strongest work
- clearly oriented toward modelling/simulation/R&D roles

Do not add content just because portfolio websites normally contain it.

When simplifying the site, prefer removing weak or redundant content rather
than hiding it behind more UI.

## Accuracy

Never invent experience, skills, results or project ownership.

For collaborative projects, distinguish my contribution from the overall
project.

Inspect the existing repository before making claims about what the website
currently contains.

## Working style

For substantial changes:

1. Inspect the current implementation first.
2. Explain what is working and what is not.
3. Identify unnecessary or distracting elements.
4. Propose a simpler structure.
5. Explain how the proposed changes better support my career objective.
6. Only then implement changes when requested.

Preserve working functionality unless there is a good reason to replace it.
